# ماژول‌های اندیکاتور — نقشه و قاعده‌ها

این پوشه بدنهٔ کامل اندیکاتور است. فایل اصلی (`../ICT_Assistant_Canonical.mq5`) دیگر کد ندارد؛
فقط سرصفحهٔ `#property` و فهرست `#include` را نگه می‌دارد.

## قاعدهٔ طلایی

**ترتیب includeها را عوض نکن و ماژول را جابه‌جا نکن.**

این ماژول‌ها **برش‌های پیوسته** فایل قبلی هستند و به همان ترتیب اصلی include می‌شوند. به همین دلیل:

- ترتیب اعلان global/struct/enum دست‌نخورده مانده، پس ترتیب وابستگی‌ها و مقدارگذاری‌های اولیه سالم است.
- واحد کامپایل عیناً همان متن قبلی است؛ هیچ رفتاری عوض نشده.
- شمارهٔ خط‌ها هم مثل قبل است، چون هر خط `#include` جای خود را به خطوط همان ماژول می‌دهد.

اگر جابه‌جایی، حذف یا اضافه‌ای لازم شد، فقط با اجرای `tools/Verify-ModuleSplit.ps1` انجامش بده —
آن ابزار ثابت می‌کند مجموعهٔ ماژول‌ها هنوز به همان متن مرجع بازمی‌گردد.

## مرجع در برابر بدنه — دو چیز که نباید قاطی شوند

مرجعِ هش در `tools/Verify-ModuleSplit.ps1` یعنی **متن بازبینی‌شدهٔ فعلی**، نه «همان فایل مونولیت تا ابد».
دو بار تنظیم شده و هر بار دلیلش بیرونی و مستند است:

| بازتنظیم | هش | دلیل |
|---|---|---|
| اول | `13A34E6B…` | خودِ بازآرایی مونولیت به اسکلت + ۳۰ ماژول — **صفر تغییر منطق** |
| دوم | `25D59CEC…` | فاز ۴۰: رفع ایراد بحرانی «پریدن آبجکت‌ها با تعویض تایم‌فریم» — یک تغییر منطقی **عمدی** |
| سوم | `9E675F79…` | فاز ۴۲: بازنویسی متن آموزشی فارسی (هیچ واژهٔ لاتین داخل جملهٔ فارسی) + فاز ۴۴: تضمین مسیر کلیک — diff بیرونی |
| چهارم | `C0725861…` | فاز ۴۶: درجهٔ سیگنال A+/A/B+/B/C — diff بیرونی، ۱۲ هانک |
| پنجم | `32A7FB3F…` | فاز ۴۷: سناریوی در انتظار + نام دفتر شاهد با تایم‌فریم — diff بیرونی، فقط هانک‌های فاز ۴۷ |
| ششم | `A24B066B…` | فاز ۴۸: پالت رنگی چارت + ادغام دو ردیف در یک «خط مسیر» — diff بیرونی، ۳۰ هانک |

منطق بازتنظیم: هش ثابت می‌کند کسی بی‌صدا متن را عوض نکرده؛ ولی **مجوزِ عوض‌کردن** از هش نمی‌آید، از
یک diff بیرونی می‌آید. اگر روزی این عدد را دستی عوض کنی و diff نداشته باشی، داری ضمانت را بی‌ارزش می‌کنی.

## چطور خودت اثباتش کنی

```bash
# ۱) ثابت می‌کند ماژول‌ها دقیقاً به همان متن مرجع بازمی‌گردند (بایت‌به‌بایت)
powershell -File tools/Verify-ModuleSplit.ps1

# ۲) و اگر می‌خواهی تغییر را با چشم خودت ببینی: منبع پیش از تغییر را از تاریخچه بیرون بکش
git show c166624:01_CANONICAL_CANDIDATES/ICT_Assistant_Canonical.mq5 > /tmp/before.mq5
powershell -File tools/Verify-ModuleSplit.ps1 -ReferencePath /tmp/before.mq5
#   S10/S11 گزارش می‌دهند «کدام بایت‌ها فرق دارند» — برای بازآرایی خالص: هیچ‌کدام
```

ابزار این چهار چیز را بررسی می‌کند:

۱. **هویت بایتی:** سرصفحهٔ اسکلت + ماژول‌های include‌شده به همان SHA256 مرجع هش می‌شوند.
۲. **هیچ کدی بیرون ماژول‌ها نیست:** بعد از آخرین include فقط خط خالی یا توضیح مجاز است.
۳. **فهرست فایل و واحد کامپایل نمی‌توانند از هم جدا شوند:** هر `.mqh` روی دیسک باید include شده باشد و هر include باید حل شود.
۴. **هر ماژول یک خانواده است:** هر فایل با بنر بخش شروع می‌شود.

## نکتهٔ اجرایی

ماژول‌ها فقط برای **خود اندیکاتور** هستند و جداگانه include نمی‌شوند؛ واحد کامپایل همان اسکلت است.
ابزار ساخت (`tools/Sync-And-Compile-Canonical.ps1`) پیش از هر بیلد، خودش `Verify-ModuleSplit` را اجرا می‌کند و
اگر برش از متن مرجع فاصله گرفته باشد **از بیلد کردن امتناع می‌کند**.

## قاعدهٔ ورودی‌های کپی‌شده (درس فاز ۴۰ — برای هر ویرایشگر بعدی)

هرجا سری‌ای با `CopyHigh/CopyLow/CopyOpen/CopyClose/CopyBuffer/CopyTickVolume/CopyRates` **داخل تابع**
کپی می‌شود، طول واقعی همان آرایه مرجع است — نه عدد درخواستی. `Copy*` فقط به تعداد کندل‌های
*آمادهٔ* پر می‌کند و بلافاصله پس از تعویض تایم‌فریم این تعداد کمتر از درخواست است.
اگر حلقه را با عدد درخواستی ببندی، `array out of range` می‌گیری و **کل پاس `OnCalculate` می‌میرد** —
و چون `OnDeinit` لایهٔ گرافیکی را پاک کرده، نتیجه «چارت خالی بعد از تعویض تایم‌فریم» است.
الگوی درست:

```mql5
int copied = CopyTickVolume(_Symbol, PERIOD_CURRENT, 0, need, v);
if(copied <= 0) return;
if(shift >= copied) return;          // مرز = طول واقعی، نه need
int bars = MathMin(copied, MathMin(ArraySize(h), ArraySize(l)));
```

هر آرایهٔ سراسری هم باید در `OnInit` صفر و در `OnDeinit` (از جمله هندل‌های indicator) آزاد شود؛
هر attach یک `OnDeinit` + `OnInit` جدید است و تعویض تایم‌فریم همان مسیر را می‌رود.
